## Delivered behavior

A deployment's Overview now shows a localized compression/artifact review panel beside the existing full physical plan and fee ceiling. It displays the recorded strategy, snapshot SHA-256, gateway ID, model-estimate limits and reasons a new plan cannot be requested. A snapshot digest is labeled a recorded identity, not an independent storage audit.

Maintainers and owners can select original, individual gzip, whole-bundle gzip or grouped gzip, select a currently configured matching gateway, and explicitly choose SPA fallback. The action creates a separate BUILT deployment from the retained raw build archive and queues planning only. It does not alter the original deployment or copy its snapshot, Manifest, signature, approved cap or recovery journal. The separate deployment must receive its own immutable prepared bytes, plan and signature through the existing lifecycle before execution.

The original plan remains available. Original mode remains the default; no automatic compression or savings promise is introduced. Existing root/versioned release, signature approval, budget and execution mechanisms remain in place.

## Operator configuration

API and Worker share the optional `TAPECI_COMPRESSION_GATEWAYS_JSON` environment setting. It is a JSON array of profiles with exactly these fields:

```json
[
  {
    "id": "replace-with-qualified-profile-id",
    "origin": "https://replace-with-qualified-gateway.example",
    "chainId": 196,
    "siteRegistry": "0x1111111111111111111111111111111111111111",
    "container": "0x2222222222222222222222222222222222222222",
    "adapterSha256": "0xabababababababababababababababababababababababababababababababab",
    "serviceFeeWei": "0"
  }
]
```

This is a format example only. None of those placeholders qualifies a real target. Use the actual verified adapter digest, origin, registry and container after the production compatibility gate is met. Set the same configuration in API and Worker processes. Origins must be exact origins without paths/credentials and use HTTPS, except HTTP loopback for local tests. IDs must be unique. Unknown keys, malformed types/addresses and invalid metadata fail configuration parsing.

Absent/empty configuration means no compression options. Nonzero service-fee profiles remain unsupported for execution and are excluded from selectable options. Operator configuration is not proof of a live installed gateway. This stage did not configure or deploy a production gateway.

Apply the preceding Stage C2 migration 0020 through the normal release workflow before using the updated Worker/API on persistent data. Only disposable test databases were migrated in this work.

## API contract

`GET /v1/deployments/:id/preparation` requires project read access. It returns normalized `request`, recorded `snapshotSha256`, `manifestSha256`, `canPrepare`, `unavailableReason`, selectable target-matching `gateways` (ID, origin, adapter hash), and `quoteType: model-estimate`. Storage keys and credentials are not returned.

`POST /v1/deployments/:id/preparation` requires maintainer/owner access:

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "preparation": {
    "schemaVersion": "tapeci.preparation.v1",
    "mode": "gzip-whole",
    "spaFallback": false,
    "gatewayId": "replace-with-qualified-profile-id"
  }
}
```

A new request requires a nonarchived project, a PLAN_READY/AWAITING_APPROVAL source that is not a rollback, an unchanged current container, a retained raw artifact/hash and, for gzip, a matching zero-service-fee gateway. Unknown body fields or preparation fields are rejected. Original requests omit gatewayId and use spaFallback false.

Response 202 returns `deploymentId`, `state`, `approvalRequired: true` and `enqueued`. It means planning was requested or an existing attempt was recovered; it never means execution or approval completed. The UUID v4 request ID deduplicates per source. Reuse with a different normalized preparation returns 409. Matching retries can recover the same deployment ID even after source eligibility or gateway configuration changes. Requeue requires current write access, a nonarchived/current target, supported current gateway, BUILT state and retained raw bytes or an existing frozen pin. A revoked gateway does not prevent finding an existing ID, but blocks requeue.

These are Fastify REST routes, not changes to an opencode Protocol/HttpApi or generated client package. No generated clients or Changesets were added.
