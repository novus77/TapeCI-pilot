# Compression Stage B: browser resolver prototype

Date: 2026-10-28. Branch: compression-release. Status: local browser/gateway-hook prototype verified. Production compressed publication remains disabled.

## Delivered

- Shared `pack-index.ts` boundary validation for Node and browser; original Stage A format remains compatible.
- Browser-native SHA-256 pin verification, metadata/source-digest checks, gzip/identity object loading, bounded transport/decode streams and per-file byte verification.
- Lazy verified-object cache with concurrent request coalescing, isolated returned byte copies and fresh verified retries after failures.
- `servePackRequest` gateway integration hook preserving logical source URLs, MIME, query handling, GET/HEAD and static directory indexes. Opt-in SPA fallback applies only to HTML navigation with a decoded extensionless path.
- Loopback-only preview command with an explicit local index pin, a bundled browser runtime, reserved tool namespace and a strict local CSP. Worker registration occurs only on its newly allocated local origin; original application root-relative URLs remain unchanged.
- Real browser fixtures for CSS, relative font URL, image, fetch, dynamic module import, Worker, WASM, deep-route refresh, static directory pages and integrity-failure blocking.

The preview's worker simulates a gateway-owned resolver. It does not replace or integrate the live TapeKit worker. Host gateway reserved paths, policy, pinned-chain verification and approved release state must remain owned by the real gateway.

## Independent review

A fresh reviewer found a concrete SPA classification bug: `/missing%2Ejson` navigations were classified using the raw rather than decoded extension, returning fallback HTML instead of 404. A real Chrome regression reproduced status 200 before the fix and 404 after it; all three engines passed the final version. Reviewer rechecked the decoded-basename fix and cache retry behavior and found no remaining actionable issues in that scope.

## Loading cost and constraints

Measured minified browser runtime: 9,066 bytes in this run. This excludes the boot document, worker wrapper, pack index, physical release Manifest and transaction overhead. Small applications may cost more with compression; no production strategy is selected from codec ratio alone.

The runtime needs Web Crypto and native gzip DecompressionStream. Unsupported capability fails explicitly; no unmeasured fallback library is included. Index transport is capped at 4 MiB; existing file/object/decoded limits apply. Bounded decoded bytes do not constitute a physical-device peak-memory benchmark.

Source authenticity depends on the independently trusted index hash. The preview CLI supplies a local pin, not an on-chain or EIP-712 approval. No browser verification header is labeled chain-verified.

## Remaining production gates

1. Integrate a resolver hook into actual TapeKit client/server gateway code while preserving reserved paths, CSP, purity/status reporting and independent pinned-chain verification.
2. Anchor pack index and loader in the approved physical Manifest; persist final bytes and strategy across approval/retry. No recompression after approval.
3. Compare complete physical release fees, including runtime/index/entry, actual object reuse, service charges and original publishing mode.
4. Fork tests for upload/resume, entry cutover, stale approvals and rollback with retained objects. Budgeted mainnet writes require explicit authorization.
5. Qualify additional real applications, deployment policies, devices and decoder fallback before enabling automatic production compression.

No mainnet transactions, DNS changes, live gateway worker installations, remote deployment, commits or pushes were performed by this milestone.
