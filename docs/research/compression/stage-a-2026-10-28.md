## Reproducible analysis command

```bash
corepack pnpm --filter @tapeci/compression analyze \
  --input /absolute/path/to/dist --output /tmp/compression-first
corepack pnpm --filter @tapeci/compression analyze \
  --input /absolute/path/to/next-dist --output /tmp/compression-next \
  --previous /tmp/compression-first/report.json
```

Output parent must already exist; output must not exist or overlap source. Candidate objects and index are persisted, decoded and verified before report.json is written. Format remains experimental and no fee estimate is fabricated.

## TapeKit loading-route study

Read-only official source clone at commit `37c617e7e332787c8a32a81e4d7d05a28a06c156`. This source pin is not proof the live gateway uses exactly this deployment.

- [serve.js](https://github.com/TapeOutProtocol/TapeKit/blob/37c617e7e332787c8a32a81e4d7d05a28a06c156/sw-gateway/serve.js#L59): fileResponse returns verified file bytes with MIME and size, but no per-file Content-Encoding negotiation/decoding mechanism.
- [boot.js](https://github.com/TapeOutProtocol/TapeKit/blob/37c617e7e332787c8a32a81e4d7d05a28a06c156/sw-gateway/boot.js#L40): gateway registers `/sw.js` with scope `/`.
- Gateway files including `/sw.js` are reserved; source explains why user sites cannot replace the gateway worker.
- Both client and server modes use fileResponse. Merely uploading a gzip file does not make application references work.

Decision: NO-GO for transparent native compression on the inspected unmodified gateway. Do not register a competing root worker. Stage B should first prototype either an explicit TapeKit pack-index resolver integration, or a tightly scoped self-contained loader with a documented application subset. No choice is production-qualified yet. Existing uncompressed publishing remains available.

## Independent review and fixes

A fresh reviewer found three material issues, all corrected with regressions:

1. Verify persisted indexBytes and candidateId against the canonical index before writing a success report.
2. Apply source metadata file/byte limits before loading the directory's contents into memory.
3. Library scan policy is unknown/null unless explicit context is supplied; CLI records its actual scan policy.

Reviewer rechecked the fixes and independently reran the 25 compression tests: all passed, with no remaining material findings.

Clarified alias coverage: shared physical bytes can have different hash-verified logical segment boundaries. Full byte coverage with no holes is required; aliases may overlap. Added a corresponding decode test.
