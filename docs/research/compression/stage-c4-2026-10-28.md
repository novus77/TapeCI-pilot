## Outcome

All four strategies were published by the existing publisher to the same isolated Anvil container, with its exact initial block/state restored before each candidate. The pinned official TapeKit chain kernel then read the real physical files from that fork at each postpublication block. The actual bundled adapter decoded compressed logical files, and the upstream response function produced responses whose bytes, MIME, digest and security/cache headers were checked.

This closes the gap between an in-memory gateway fixture and real contract-backed chain reads on a local fork. It does not qualify an installed public gateway, Cloudflare deployment, paid-name resolution, browser Service Worker lifecycle, independent RPC operators or mainnet fees.

Automatic selection remains original.

## Price and receipt accounting

Every release receipt must be successful and unique, with coverage equal to the executor's new transaction count and the complete fresh-target plan's chunk count. Reported `gasUsed` is the sum of receipt gas. `minedFeeWei` is the sum of gasUsed × each receipt's actual effectiveGasPrice. `normalizedCostWei` multiplies measured total gas by one common baseline quote price, `1015363368` wei/gas, so candidate gas-price movement cannot be presented as compression savings.

Both figures are local fork accounting. They are not real OKB spending, production fee quotes or a complete X Layer L2 fee calculation. No per-chain extra fee field or setup cost is claimed. The existing gas model was not recalibrated from this single fixture.

Snapshot/revert is checked after every candidate, including failure paths. Every next candidate must begin at the original baseline block hash and have no unchanged/conflicting files. Journals are separate per strategy. Actual snapshot restoration includes the same funded signer/nonce state; the baseline block remains the same.

Kernel reads use one local endpoint, quorum 1, and the known fixture container/block directly. They do not call the name/processor identity resolver and must not be treated as a paid-name or domain activation check. The native manifest/read/hash path is exercised without mocking the RPC or file reader. The adapter is built from the source overlay and imported from that isolated output.

For each logical response the harness checks status, normalized expected MIME, UTF-8 charset on text/application script data, content length, x-tape-sha256, verified/mode, CSP, nosniff, referrer policy, cache control and exact body hash. A reviewer found that the first implementation could accept correct bytes with a wrong MIME or stale digest header. Real Response regressions reproduced that false-positive boundary, and the strict helper now rejects it. All four strategies were rerun after the fix.

These are Response objects from the actual source function, not deployed HTTP/TLS responses or a browser execution test.

The output must be a new file in an existing directory; successful evidence is written exclusively after all candidates and restorations pass. Existing output is never overwritten.
