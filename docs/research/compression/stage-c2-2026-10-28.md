## Outcome

The Worker freezes final release bytes before approval in a deterministic, content-addressed tar archive. Planning, execution, verification, reapproval continuation and rollback reuse those bytes. Missing or corrupt frozen data fails without rebuilding or recompressing the source. Original publication remains the default.

This stage implements backend integration and local validation. It does not enable a public compression control, qualify a production gateway, run a production migration or send mainnet transactions.

## Implementation

- `apps/api/src/worker/prepared-artifact.ts`: snapshot codec, fixed numbered binary payload paths, metadata bounds, safe tar ingestion, exact manifest/context/coverage/hash verification. Packed files use mode 0644, portable tar and no timestamps, including across different process umasks.
- `apps/api/src/worker/preparation-policy.ts`: strict original/gzip preparation request parsing and operator-supplied target gateway profiles. Array-valued modes and unknown fields are rejected. The default qualification list is empty. Nonzero gateway service fees are blocked in Worker pending a separate approval flow.
- `apps/api/src/worker/prepare-release.ts`: separate original and compressed preparation paths. Original root/versioned behavior remains available.
- `apps/api/src/worker/runtime.ts`: validate installation, source identity, request and qualification; freeze bytes; CAS-bind snapshot before approval; reload the snapshot on later access. The raw source need not remain available after binding. Legacy original records can prepare once; legacy approved compressed records without a snapshot fail closed.
- Migration `0020_prepared_artifacts`: nullable `preparation_request` and `prepared_artifact_key`, with a content-addressed key constraint. Queue mapping, recovery and rollback preserve both fields.
- `packages/deployer/src/comparison.ts`: compare complete physical plans at the same chain/target/block/operators/gas price, including explicit service fees. Results are model estimates, not production simulations. Automatic selection remains original.

The snapshot context pins project, repository, commit, chain, registry, container, raw archive key/hash, normalized preparation request and selected gateway metadata. Deployment ID is intentionally omitted so an authorized continuation can adopt the identical snapshot. Existing access, installation, cap, journal and execution checks remain active.
