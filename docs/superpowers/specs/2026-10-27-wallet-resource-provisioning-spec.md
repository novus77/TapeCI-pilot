# TapeCI 钱包资源准备与发布规格

版本：0.1；日期：2026-10-27。本文为新增范围的开发规格，不表示功能已实现。  
来源：[产品设计](../../reports/TapeCI-Wallet-Onboarding-and-Release-Design-2026-10-27.md)、[流程审查](../../reports/TapeCI-User-Journey-Audit-2026-10-27.md)。  
实施计划：[开发计划及多 Agent 问题清单](../plans/2026-10-27-wallet-resource-provisioning.md)。

## 1. 范围变更与边界

旧 PRD §2.3 将 NFT 获取、流片和容器开通排除在 MVP 之外。本规格根据用户本轮指示扩展该范围：平台支持发现已有资源、准备缺项和对接真实采购来源。旧 PRD 的静态构建、链上写入、权限、费用和验证约束继续适用。

一站式准备统一选择、报价、进度及交付验收，不预设单笔原子交易；不保存用户主钱包私钥。首期网络为 X Layer 196，默认由用户钱包逐步支付。平台代付、赠送到未经验证的地址、独立钱包登录和跨链采购暂不包含。

## 2. 用户闭环

连接钱包/输入地址 → 发现电路 → 复用已有资源或补齐缺项 → 报价 → 登录并验证交付钱包 → 准备任务 → 资源验收 → 项目配置 → 启用构建 → 审阅及签名 → 执行与链上验证 → 域名激活 → 访问网站。

允许先配置项目草稿。资源准备、构建成功、发布验证、域名激活与网站可访问是不同结果，不能共用一个“成功”状态。

## 3. 功能需求

| ID | 必须实现的行为 | 验收要点 |
| --- | --- | --- |
| R01 | 连接钱包和手工地址查询；手填仅查看 | 未连接可读公开资产；输入他人地址不获得写权限 |
| R02 | 公共处理器目录 + 钱包持有的电路 + 推导容器 | 显示处理器编号和电路编号；索引候选在选择时再次 ownerOf 核验 |
| R03 | 区分同步中、部分结果、失败和无资产 | 查询失败不得提示购买以替代丢失资产；支持分页与手工编号补查 |
| R04 | 登录身份和钱包控制权验证 | 复用现有 challenge/verify；钱包切换不能静默改变交付地址 |
| R05 | 公开链上数据与私有项目关联分离 | 未授权用户不可见仓库、成员、项目名称或任务详情 |
| R06 | 现有已开启容器直接选用，未开启仅补齐开启 | 分别检查 deployed/opened；不重复购买已有电路 |
| R07 | 供应目录与有效期报价 | 明示供应方、商品、接收钱包、币种、各项收费、gas 与后续费用 |
| R08 | 准备任务和每步结果持久化 | 刷新、重启、拒签后可继续；确认前不得标记交付成功 |
| R09 | 交易核验与恢复 | submitted 先核验原交易；不因超时重复付款；部分成功保留已获得资源 |
| R10 | 平台预备库存交付检查 | 所有权、旧授权、内容及域名按交付约定核验；无真实供应接口则禁用采购 |
| R11 | 项目草稿及服务端构建启用控制 | 草稿推送记账但不启动构建；用户启用并选择确定 commit 后再构建 |
| R12 | 构建日志、源任务关联和新尝试 | 失败可定位 job；重试关联原尝试并遵循最新配置和确定 commit |
| R13 | 签名前摘要及真实能力判定 | 展示签名对应的 manifest、容器、账户、网络、费用 cap、到期时间；API 继续最终授权 |
| R14 | 精确费用与预算 | 非零不显示成免费；估计、授权上限、实际支出分列；未知值不显示为零 |
| R15 | 激活页可直接连接钱包 | 注入钱包和 WalletConnect 分别验证；无注入 provider 不等于无可用 WalletConnect |
| R16 | 项目级发布与访问结果 | 当前版本、域名有效期、网址、最后访问检查及阻塞项集中展示 |
| R17 | 过期、撤权、上传/验证失败恢复 | 明确下一步、责任方、是否重新签名和新增费用；未实现的续传不承诺可用 |
| R18 | 保留已有功能与响应式可用性 | 证据、比较、预算、审计、成员、通知、签名回退均保留；390/1440、中英文和键盘验收 |

## 4. 数据与接口契约

所有下列新增名字为计划契约，不是现有公开 API。实施前由共享契约模块统一导出，web 不导入 API/worker 私有运行时代码。

- 资产唯一键：chainId + processor address + tokenId；tokenId、wei 和区块号以十进制字符串传输。processorIndex 不充当 NFT 所有权证明。
- `WalletResourcePage`：resources、nextCursor、observedBlock、syncStatus、complete；每项包含 processor、processorIndex、tokenId、container、owner、deployed、opened；未查询成功的状态允许 unknown。
- 公共查询接口返回链上字段；项目关联通过单独的已授权查询合并，不能公开返回关联项目。
- `PreparationQuote`：id、chainId、recipient、source、items、steps、prices、expiresAt、termsVersion；价格是带币种和精确整数金额的项，gas 为估计，不能混合币种直接相加。
- `PreparationTask`：id、userId、quoteId、recipient、chainId、idempotencyKey、state、createdAt；创建动作不等于付费交易授权。
- `PreparationStep`：taskId、ordinal、kind、state、expectedResource、transactionAttempts、confirmedBlock、result、errorCode；种类至少区分 acquisition、open、activation，已有步骤标记 skipped。
- 步骤状态：waiting → awaiting_signature → submitted → confirmed；可进入 failed 或 skipped。任务完成条件是所有必要步骤 confirmed/skipped 且资源验收通过。
- 独立记录交易尝试；构造时保存预期 chain、to、value、calldata 摘要及交付对象，提交时用 receipt 和目标事件/最终资源状态核验。仅收到客户端 txHash 不等于交付成功。
- 核验实际交易的 chain、from、to、value、calldata 与该步骤意图及报价匹配，交易尝试不可被不同任务重复归因为付款。用户在外部自行补齐资源可重新检查后跳过步骤，但不记为本订单已付款。
- 记录 receipt 的 blockHash/number，按固定区块核验资源及规范链。确认深度由该网络的显式配置决定；未配置时不开放采购完成判定。双 RPC 一致与确认深度均满足才进入 confirmed；重组或分歧时回到待核验，暂停下一付费步骤，不自动重发。
- 幂等范围绑定登录用户和请求内容；相同键不同报价/交付钱包必须冲突，重试不能改写旧任务。
- 项目草稿单独建模，不直接把当前正式项目 containerId 改为可空；转为正式项目时复用现有授权和容器解析。
- 构建是否启用持久化到正式项目；Webhook、OIDC/build token、手动触发入口遵循同一规则。旧项目迁移保持原有行为，新草稿默认不启用。

## 5. 服务边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| Resource discovery | 目录、候选索引、链上复核、公开查询 | 创建项目权限、执行购买 |
| Wallet identity | 登录用户的钱包控制权与账户状态 | 采购或发布授权 |
| Provisioning | 目录适配、报价、任务、步骤、交易验收 | 冒充部署状态机或持有用户主钥 |
| Projects/builds | 草稿、配置、明确启用、固定 commit 构建、日志和尝试关联 | 自动采购缺失资源 |
| Deployments | 现有计划、审批、串行写入、双 RPC 验证和恢复 | 将网站 HTTP 可访问性等同于链上验证 |
| Web console | 当前任务状态、下一步、钱包确认前摘要 | 作为最终权限或支付成功依据 |

## 6. 上线门槛

- 支持发现和复用资源可以先交付；采购按钮只有在对应供应来源、报价和交付核验全部可用时开放。
- 采购合约/接口和价格规则仍需提供或核验；不得猜测 mint/purchase ABI。
- 平台库存需要实际供应与交付规则，不能用 Mock 的“成功”上线。
- 用户付款、购买、部署 gas、域名续期分别记录。真实主网新交易必须明确目标和费用限制；设备签名由用户完成。
- 当前仓库使用 pnpm/Vitest，用户最新检查规则要求 Bun/package-local 验证。执行阶段先统一命令入口，不运行不存在的脚本，也不把命令未适配记为检查通过。

## 7. 验收场景

| AC | 场景 | 覆盖需求 |
| --- | --- | --- |
| AC01 | 已有可用容器，零采购直接发布 | R01–R06、R11–R16 |
| AC02 | 有电路未开启，只补齐开启后发布 | R02、R06、R08–R09 |
| AC03 | 无资产，完成采购、交付核验、开启与发布 | R07–R13 |
| AC04 | 输入他人地址和跨项目访问 | R01、R04–R05 |
| AC05 | 索引失败/部分同步，手工补查，资产转移后重新选择 | R02–R03、R06 |
| AC06 | 报价过期、钱包切换、拒签和余额不足 | R04、R07–R09、R14 |
| AC07 | 购买确认但开启失败，刷新/API 重启后继续 | R08–R09 |
| AC08 | 草稿收到推送与 OIDC 请求，启用后选择 commit | R11 |
| AC09 | 构建失败看日志，重试产生关联的新尝试 | R12 |
| AC10 | 签名过期、权限撤销、上传/验证中断和恢复 | R13、R17 |
| AC11 | 发布已验证但未激活，完成激活后访问检查 | R15–R16 |
| AC12 | 中英文、390/1440、键盘和三类真实设备接入 | R18 |

本规格不将上述场景标记为已通过。开发计划应将每项需求和审查问题映射到任务、测试与上线依赖。
