## 2. Goals

1. **Mobile tables must be usable without horizontal scrolling.** This is the single biggest
   usability defect: at 390px the members table shows two of five columns and gives no signal
   that more exist.
2. **Every interactive target reaches 24×24 CSS px** on touch viewports.
3. **One number, one meaning.** A count shown twice on the same screen must not differ.
4. **No dead space at desktop widths.** A 1440px viewport must not render an 832px column with
   600px of emptiness beside it.
5. Keep every existing gate green and every existing test passing (or update it with a stated
   reason).

## 3. Non-goals

- No new runtime dependency.
- No change to the deployment state machine, chain writes, or API authorization.
- No redesign of the desktop information architecture: the GitLab benchmark is closed and its
  layout decisions stand.
- Not adding illustrations or decoration beyond what §4 requires.

## 4. Requirements

### R1 — Responsive table presentation (priority: high)

At **≤ 720px**, the deployment table, member table, and any other `.table` with more than three
columns must render as a **stacked card list** instead of a horizontally scrolling table.

- Each row becomes a card: a primary line (project/login) and a label–value list for the
  remaining cells.
- Every value keeps its column label, so nothing loses meaning when the header disappears.
- The card list must be reachable by keyboard exactly like the table was, and must keep the
  same `data-testid` hooks (`deployment-row`, `member-row`) so existing tests keep asserting the
  same thing.
- The desktop table stays a table at > 720px: this is a presentation switch, not a data change.
- Sortable headers: at ≤720px the sort control moves to a compact `<select>` above the list
  (a header row no longer exists). The URL contract is unchanged.

### R2 — Scroll affordance where a table still scrolls (priority: medium)

Any `.table-wrap` that actually overflows must show it: a right-edge shadow that fades when the
container is scrolled to the end, and `tabindex=0` retained for keyboard scrolling. Pure CSS
where possible; a small client hook is acceptable if CSS cannot detect scroll position.

### R3 — Touch target minimum (priority: high)

Every `a`, `button`, `input`, `select` inside the console must be at least 24×24 CSS px on
viewports ≤ 720px. Measured offenders today: locale buttons (28×22), sort headers (43–73×16),
inline row links (49×16), breadcrumb links (95×17).

- Achieve it with padding/min-height, not by scaling text.
- The 24px minimum applies to the hit area, which may exceed the visual box (use padding).
- Do not break the existing 390px no-overflow guarantee.

### R4 — Count consistency (priority: medium)

The sidebar count and the KPI must never disagree on the same screen.

- The KPI that reads "latest ten records at most" must be labelled so the difference is
  unmistakable, **or** the sidebar must show the same snapshot count. Pick one and state it in
  the UI copy; do not silently show 12 next to 10.
- Requirement: after the change, a user reading both numbers understands why they may differ, or
  they are equal.

### R5 — Desktop settings layout (priority: medium)

At ≥ 1080px the settings page must not render a single 832px column with dead space.

- Restore a two-column content area beside the section rail (rail 200px + two content columns),
  **or** widen the single column to use the available width and place short sections side by side.
- The section rail must keep tracking the visible section (existing behaviour) and must not
  regress the sticky offsets (`top: 64px`, heading `scroll-margin-top: 72px`).

### R6 — Mobile KPI density (priority: low)

At ≤ 720px the four KPI cards must present as a 2×2 grid so the first content section is
reachable without scrolling past four full-width cards.

### R7 — Mobile nav truncation hint (priority: low)

The horizontal nav strip must indicate that it scrolls: an edge fade or a scrollbar, so the
clipped `+` is not mistaken for the end of the list.

### R8 — Breadcrumb slug (priority: low)

In mock mode the organization breadcrumb must show the slug for the requested id, not a fixed
`mock-org`. This is fixture correctness, not a production defect.

## 5. Acceptance criteria

Each requirement is accepted only when all of the following hold:

| # | Criterion |
|---|---|
| A1 | `scrollWidth <= clientWidth + 1` on `documentElement` for every route at 320, 390, 480, 720, 768, 1024, 1440 |
| A2 | At 390px, **no** `.table` is horizontally scrollable (R1 makes them cards); any remaining scroll container shows the affordance from R2 |
| A3 | Every interactive element measures ≥ 24×24 at 390px and 720px (automated assertion, not eyeballing) |
| A4 | Sidebar and KPI numbers are consistent or explicitly explained (R4) |
| A5 | At 1440px the settings content area uses ≥ 85% of the width available beside the rail |
| A6 | Existing e2e selectors (`deployment-row`, `member-row`, `member-table`, `pager`, `sort-link`, `aria-sort`) still resolve |
| A7 | `impeccable detect` on `apps/web/app` + `apps/web/components` reports 0 findings |
| A8 | axe clean (no serious/critical) on every page at 390px **and** 1440px, including the card-list rendering |
| A9 | typecheck (root + web), lint, unit, p2, and the full Playwright suite pass |
| A10 | Both locales render every new string; the dictionary parity test stays green |

## 7. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Card list breaks existing e2e selectors | Keep `data-testid` on the card root and on each labelled value; assert both table and card modes in one spec |
| Touch-target padding increases row height and hurts desktop density | Scope the minimum to `@media (max-width: 720px)` and `(pointer: coarse)` |
| Two-column settings re-breaks the section rail tracking | The rail already derives its probe from `scroll-margin-top`; re-run the rail spec after the change |
| Count unification hides a real difference (snapshot vs total) | Prefer explicit copy over changing a number's meaning; document the choice in `GITLAB-BENCHMARK.md` |

### Things this round deliberately did not fix

Found while implementing, recorded rather than silently dropped:

1. Two sections sharing a row make "which section am I in" ambiguous for the settings rail. The
   rail now picks the heading closest to the probe from above, which is stable, but a reader
   looking at two side-by-side panels has no single answer. Acceptable while the grid is two
   columns; revisit if sections grow.
2. `formatWeiAsOkb` truncates to four decimals, so a positive amount below 0.0001 OKB renders as
   `0.0000 OKB` — a real defect, tracked as J05 in the journey audit.
3. Container activation still has no wallet-connect control and a failed build still has no
   retry path — the two P0s in the journey audit, both larger than a UI polish round.
